# 講習スケジュール（Cloudflare 版）

講師の予定提出、事務によるコマ組み、comiruへの授業反映を行うアプリです。
Cloudflare Workers + D1（データベース）の無料枠で動きます。

- 講師ページ `/`：Googleでログインし、講習ごとに来られるコマを提出。事務が「ログイン用メール」を登録すれば、そのGoogleアカウントですぐ使えます。未設定の場合はcomiruのメールと照合します。
- 管理画面 `/admin`：「時間割」「名簿・予定」「設定」の3つに分けています。
- Flask版への引き継ぎは「名簿・予定」のCSV出力、元のGASへの引き継ぎは時間割の「コピペ用」を使います。

## 時間割の使い方

「生徒から見る」では、生徒と科目を選んでコマに講師を配置します。「講師から見る」では、講師ごとに全生徒の授業と空き時間を確認できます。空きコマを押すと、通塾予定と担当科目が合い、その時間に授業が入っていない生徒を選べます。勤務外・休校日・満席には追加できません。

時間割は一週ずつ表示します。「前の週」「次の週」または週の選択で移動でき、保存や生徒・講師の切替でも表示中の週を保ちます。席の初期値は先頭の空席です（A・B・Cが使用中ならD、A・B・Dが使用中ならC）。最終的な空席は保存時にも確認します。

講師の授業を押すと詳細が開き、その生徒の時間割へ移るか授業を削除できます。表示を切り替えても選択中の講師・生徒を覚えています。どちらの表示でも自動保存・元に戻す・他PCの変更取り込みは共通です。

点線と「確認・保存中」が出ているコマは保存待ちです。アプリへの保存後も、comiruにはまだ反映されていません。「comiru反映を確認」で対象をこの生徒／全生徒から選び、追加・変更・削除・保留を確認して実行します。講師から見ている場合の初期対象は全生徒です。

「コピペ用」はcomiru連携が未設定のときも利用できます。コピーには反映済みの授業も含まれます。元のGASのシートの「生徒名」の列に貼る5列の形式です。GASからの実登録は別途確認が必要です。

講習の新規作成と削除は「設定」→「講習の設定」の下部にあります。削除は確認画面を通し、「削除した講習」から復元できます。削除すると予定の受付は停止し、復元後も停止状態です。予定と割り当ては保持し、comiruの授業は変更・削除しません。

講師の「詳細」でログイン用メールを設定できます。変更後は以前のアカウントで講師の予定を利用できなくなり、提出済みの予定は残ります。事務が設定したメールはcomiru名簿を更新しても保持します。非表示の講師は「非表示の講師を戻す」から一覧を開き、「一覧に戻す」で復帰できます。

電話やLINEで講師から予定の変更を受けたときは、「名簿・予定」→「講師」→「詳細」→「予定を代わりに直す」で事務が代わりに入力できます。受付を締め切った講習でも直せます。理由（例：電話で連絡）を書いて保存すると、本人の保存と同じく「変更履歴」に誰が・いつ・どのコマを増やした／減らしたかが残ります。本人と事務が同時に直したときは、あとから保存したほうを止めて、先の変更を上書きしません。事務が自分で直した分は割り当て画面の「予定変更のお知らせ」には出ません（本人の未確認の変更のお知らせは残ります）。

## ローカルで動かす

```bash
cd cloud
npm install
cp .dev.vars.example .dev.vars   # SESSION_SECRET を長いランダム文字列にする
npm run db:migrate:local
npm run dev                      # http://localhost:8787
```

`.dev.vars` で `DEV_LOGIN=1` にしておくと、ログイン画面の下に「開発用ログイン」が出て、Google を使わずに好きなメールアドレスでログインできます（localhost のときだけ有効）。
`ADMIN_EMAILS` に書いたアドレスでログインすると管理画面に入れます。

## 動作確認

```bash
npm run typecheck
npx playwright install chromium   # ブラウザテストを初めて動かすとき
npm run test:ui
npm run test:api
```

ブラウザテストはテスト用データで通信を再現し、保存の遅延・失敗、未保存の警告、コマの移動、スマホでの表示などを確認します。実際のデータベースや comiru には接続しません。
APIテストも一時的なローカルDBとcomiruのテスト用サーバーを使い、同時登録・満席・座席設定・名簿の並び順を確認します。

「設定」→「座席設定」で全講習に共通の座席数を変更できます（1〜100席、A〜Zの次はAA〜）。割り当て済みの席を削ることはできません。
講師はふりがな順、生徒は小1〜小6・中1〜中3・高1〜高3の順で並びます。同学年内はふりがな順、学年不明は末尾です。
ふりがなは講師の詳細画面、ふりがな・学年は生徒の予定画面で補えます。手入力した値はcomiruの名簿を取り直しても維持します。

## 公開する（初回だけ）

### 1. Cloudflare

1. https://dash.cloudflare.com/sign-up で無料アカウントを作る
2. `npx wrangler login`
3. `npx wrangler d1 create juku-scheduler` を実行し、表示された `database_id` を `wrangler.toml` に書き換える
4. `npm run db:migrate:remote`
5. `npm run deploy` → `https://juku-scheduler.<アカウント名>.workers.dev` が表示される（以下「公開URL」）

### 2. Google ログインの設定（無料）

1. https://console.cloud.google.com/ でプロジェクトを作る
2. 「APIとサービス」→「OAuth 同意画面」：ユーザーの種類は「外部」、アプリ名・サポートメールを入力し、**公開ステータスを「本番環境」にする**（テスト中のままだと、登録したテストユーザーしかログインできない）。スコープは email / profile / openid のみなので審査は不要
3. 「認証情報」→「OAuth クライアント ID を作成」→ 種類「ウェブ アプリケーション」
   - 承認済みのリダイレクト URI：`公開URL/auth/callback`
4. 表示されたクライアント ID とシークレットを登録する

```bash
npx wrangler secret put GOOGLE_CLIENT_ID
npx wrangler secret put GOOGLE_CLIENT_SECRET
npx wrangler secret put SESSION_SECRET   # 長いランダム文字列（例: openssl rand -base64 32 の結果）
npx wrangler secret put ADMIN_EMAILS     # 最初の事務アカウント（カンマ区切り）
```

**本番には `DEV_LOGIN` を絶対に設定しないこと。**

### 3. 使い始める

1. `公開URL/admin` に事務アカウントでログイン →「設定」→「新しい講習を作る」
2. 講師に `公開URL` を LINE などで共有する（全員同じリンク）
3. 名簿のメールと違うGoogleアカウントを使う講師は、「名簿・予定」→「講師」→「詳細」でログイン用メールを設定する

## 更新するとき

```bash
npm run db:migrate:remote   # migrations/ に新しいファイルを足したときだけ
npm run deploy
```
